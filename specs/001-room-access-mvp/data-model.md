# Data Model: Room Access MVP

**Feature**: `001-room-access-mvp`
**Date**: 2026-07-14

---

## Entity Overview

```
auth.users (Supabase managed)
    │
    └── sessions (host_id → auth.users.id)
            │
            └── participants (session_id → sessions.id)
```

---

## Entity: `sessions`

Represents a karaoke session created by a Host.

### Fields

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `uuid` | PK, DEFAULT `gen_random_uuid()` | Internal identifier |
| `code` | `char(6)` | NOT NULL, UNIQUE | Generated by `create_session` RPC; uppercase alphanumeric |
| `host_id` | `uuid` | NOT NULL, FK → `auth.users(id)` ON DELETE CASCADE | References the Supabase Auth user (anon or permanent) |
| `status` | `text` | NOT NULL, DEFAULT `'active'`, CHECK IN (`'active'`, `'paused'`, `'closed'`) | Session state machine |
| `max_participants` | `smallint` | NOT NULL, DEFAULT `50` | Hard limit; enforced in `join_session()` RPC |
| `max_queue_entries` | `smallint` | NOT NULL, DEFAULT `200` | Hard limit; enforced in future queue feature |
| `created_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Creation timestamp |
| `closed_at` | `timestamptz` | NULL | Populated when status transitions to `'closed'` |

### State Machine

```
active ──(pause)──→ paused
paused ──(resume)──→ active
active ──(close)──→ closed
paused ──(close)──→ closed
```

`closed` is a terminal state — no transitions out.

### Constraints & Indexes

```sql
-- Host lookup (list own sessions in future)
CREATE INDEX sessions_host_id_idx ON sessions (host_id);

-- Status filter (find active sessions)
CREATE INDEX sessions_status_idx ON sessions (status) WHERE status != 'closed';
```

### Notes

- The `code` value is normalized to uppercase at generation time. Any lookup must also uppercase-normalize user input before querying.
- A closed session's code is retained in the DB for history purposes but is not reusable (the `UNIQUE` constraint remains).
- `max_participants` and `max_queue_entries` are stored per-session to allow future per-session overrides without schema changes.

## Entity: `participants`

Represents a guest who has joined a session. Each row is a unique participant identity within a session.

### Fields

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `uuid` | PK, DEFAULT `gen_random_uuid()` | The participant's public durable identity (`participant_id`) |
| `session_id` | `uuid` | NOT NULL, FK → `sessions(id)` ON DELETE CASCADE | The session this participant belongs to |
| `display_name` | `text` | NOT NULL | Raw name as entered by the user; max 32 chars |
| `disambiguation_index` | `smallint` | NOT NULL, DEFAULT `1` | 1 = first with this name (no suffix shown); 2+ = show `#N` suffix |
| `recovery_token_hash` | `text` | NOT NULL | SHA-256 hash of the recovery token used for secure session recovery |
| `joined_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | First successful join timestamp |
| `last_seen` | `timestamptz` | NOT NULL, DEFAULT `now()` | Updated on reconnection; used to detect stale presence (future) |
| `created_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Row creation timestamp |

### Constraints & Indexes

```sql
-- Prevent duplicate participant rows (idempotency guard for retries)
-- A participant is uniquely identified by session + name + index
-- The RPC handles assignment of disambiguation_index, so this index
-- prevents double-inserts at the DB level.
CREATE UNIQUE INDEX participants_session_name_idx
  ON participants (session_id, display_name, disambiguation_index);

-- Fast lookup by participant id (reconnection flow)
CREATE INDEX participants_id_idx ON participants (id);

-- Count participants per session (enforces max_participants limit in RPC)
CREATE INDEX participants_session_id_idx ON participants (session_id);
```

### Presence / Online Status

> **Design decision (MVP)**: No `is_online` boolean column is implemented in this feature.
>
> `is_online` as a stored boolean is unreliable without a heartbeat mechanism: if a client crashes, the flag stays `true` indefinitely. Since presence is not required by any MVP requirement, it is intentionally deferred. The `last_seen` column is sufficient for future presence inference (`now() - last_seen < threshold`).
>
> When presence is needed (e.g., for the queue feature), it will be implemented via Supabase Realtime Presence, not a DB column.

### Participant Recovery

On page refresh or reconnect, the client reads `participant_id` and `recovery_token` from a cookie (`vocalis_pid`) and calls the `recoverParticipant` Server Action. The action delegates to the `recover_participant` RPC which verifies:
1. The `participant_id` exists.
2. The `recovery_token` hash matches `recovery_token_hash`.
3. The associated `session_id` matches the code in the URL.
4. The session is not `'closed'`.

If all checks pass, the RPC updates `last_seen` and the participant view is restored. If any check fails, the join form is shown.

### `display_name` Validation Rules

| Rule | Value |
|---|---|
| Min length | 1 character (after trim) |
| Max length | 32 characters |
| Allowed characters | Any Unicode (emoji supported) |
| Normalization | Leading/trailing whitespace is trimmed server-side |
| Uniqueness | Not enforced at DB level; disambiguation handled by `disambiguation_index` |

## Postgres RPC: `join_session(p_code, p_display_name)`

This function is the authoritative entry point for a guest joining a session. It runs as `SECURITY DEFINER` with `SET search_path = public, extensions`.

### Logic (atomic)

```
1. Uppercase-normalize p_code.
2. SELECT session WHERE code = p_code.
3. IF NOT FOUND → raise exception 'SESSION_NOT_FOUND'.
4. IF session.status = 'closed' → raise 'SESSION_CLOSED'.
5. IF session.status = 'paused' → raise 'SESSION_PAUSED'.
6. COUNT participants WHERE session_id = session.id.
7. IF count >= session.max_participants → raise 'SESSION_FULL'.
8. Generate v_recovery_token = encode(gen_random_bytes(32), 'hex').
9. Generate v_hash = encode(digest(v_recovery_token, 'sha256'), 'hex').
10. Compute disambiguation_index:
      SELECT COALESCE(MAX(disambiguation_index), 0) + 1
      FROM participants
      WHERE session_id = session.id AND display_name = trim(p_display_name).
11. INSERT INTO participants (session_id, display_name, disambiguation_index, recovery_token_hash)
    VALUES (session.id, trim(p_display_name), computed_index, v_hash)
    RETURNING id, display_name, disambiguation_index, joined_at.
12. RETURN new participant row PLUS v_recovery_token.
```

### Error → User Message Mapping

| Exception code | User-facing message (PT-BR) |
|---|---|
| `SESSION_NOT_FOUND` | *"Sala não encontrada. Verifique o código e tente novamente."* |
| `SESSION_CLOSED` | *"Esta sessão já foi encerrada."* |
| `SESSION_PAUSED` | *"A fila está pausada. Aguarde o DJ reabrir."* |
| `SESSION_FULL` | *"Sala cheia. Limite de 50 participantes atingido."* |

## Postgres RPC: `create_session(p_host_id)`

Creates a new session for the authenticated host. Runs as `SECURITY DEFINER` with `SET search_path = public, extensions`.

### Logic (atomic)

```
1. Generate code: attempt up to 5 times using restricted alphabet via gen_random_bytes.
   SELECT count(*) FROM sessions WHERE code = candidate_code.
   IF count = 0 → use this code.
   AFTER 5 failures → raise 'CODE_GENERATION_FAILED'.
2. INSERT INTO sessions (host_id, code, status) VALUES (p_host_id, code, 'active').
3. RETURN session row.
```

---

## Postgres RPC: `recover_participant(p_participant_id, p_recovery_token, p_code)`

Authoritatively handles recovering a participant and updating `last_seen`. Runs as `SECURITY DEFINER` with `SET search_path = public, extensions`.

### Logic (atomic)

```
1. Uppercase-normalize p_code.
2. SELECT session WHERE code = p_code.
3. IF NOT FOUND → raise 'SESSION_NOT_FOUND'.
4. IF session.status = 'closed' → raise 'SESSION_CLOSED'.
5. SELECT participant WHERE id = p_participant_id AND session_id = session.id.
6. IF NOT FOUND → raise 'PARTICIPANT_NOT_FOUND'.
7. Generate v_hash = encode(digest(p_recovery_token, 'sha256'), 'hex').
8. IF participant.recovery_token_hash != v_hash → raise 'INVALID_TOKEN'.
9. UPDATE participants SET last_seen = now() WHERE id = p_participant_id.
10. RETURN participant row.
```

## Future-Proofing Notes (no code created now)

- `participants` is designed with `last_seen` to support presence inference without schema migration.
- `sessions.max_queue_entries` is already stored so the queue feature can enforce it without altering the table.
- `disambiguation_index` on participants makes the queue display (showing the right singer) correct by default.
- All PKs are UUIDs — safe for distributed ID generation and future federation.
- `sessions` cascades deletes to `participants` but NOT to `queue` entries (future table will handle its own archival to satisfy FR-017: permanent history).
